## Technical Story - CI som quality gate

Som udviklingsteam vil vi automatisere vores testkørsel i CI, så fejl 
opdages, før kode integreres i main.

## Acceptkriterier

- [ ] Et GitHub Actions-workflow starter automatisk ved Pull Requests mod main. 
- [ ] Projektet kan bygges i CI-miljøet. 
- [ ] Automatiserede unit tests køres automatisk. 
- [ ] Relevante integrationstests køres automatisk. 
- [ ] Der udføres statisk analyse af koden.
- [ ] Nødvendigt testmiljø, fx PostgreSQL, kan etableres automatisk.
- [ ] Workflowet fejler, hvis en obligatorisk kvalitetskontrol fejler. 
- [ ] Teamet kan demonstrere både et succesfuldt og et fejlet CI-run.
- [ ] Et fejlet obligatorisk CI-check skal forhindre merge til main (dermed bliver CI 
reelt en quality gate og ikke bare en grøn/rød lampe, som kan ignoreres).
## Sub-issues

- [DEPLOYMENT] Configure a GitHub Actions workflow to run automatically for pull requests targeting main.
- [DEPLOYMENT] Configure the CI environment to build the project and establish the required test environment, including PostgreSQL when needed.
- [TESTING] Run automated unit tests and relevant integration tests in the workflow.
- [TESTING] Add static code analysis to the workflow.
- [DEPLOYMENT] Make the workflow fail when a required quality check fails.
- [DEPLOYMENT] Ensure a failed required check prevents merging into main.
- [DEPLOYMENT] Demonstrate both a successful and a failed CI run.
