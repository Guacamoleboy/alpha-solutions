## Technical Story - Testcase design

Som udviklingsteam vil vi designe testcases for centrale user
stories, så vi systematisk tester de vigtigste funktioner og
grænsetilfælde

## Acceptkriterier

- [x] Teamet har udvalgt nogle af produktets mest centrale user stories og
begrundet udvælgelsen.
- [x] Testcases kan spores tilbage til storyens krav og acceptkriterier.
- [x] Der indgår både normale og relevante fejl-/grænsetilfælde.
- [x] Equivalence Partitioning, Boundary Value Analysis og Decision Table er
anvendt, hvor teknikkerne er relevante.
- [x] Valget af testdata kan begrundes.

Se [testcasene for US-11 og US-04](../TS-09-test-cases.md).

## Sub-issues

- [TESTING] Select and justify the product's central User Stories for test case design.
- [TESTING] Derive test cases from the selected stories' requirements and acceptance criteria.
- [TESTING] Include normal cases and relevant error and boundary cases.
- [TESTING] Apply equivalence partitioning, boundary value analysis and decision tables where relevant.
- [TESTING] Select test data and document the rationale for the selection.
