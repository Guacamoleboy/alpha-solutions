## Technical Story 04 - Deploy the Applications

As a development team, we want to deploy the frontend and backend applications to a server environment, so that users can access the applications through their domains.

## Acceptance Criteria

- [ ] A Docker image for the frontend is built and available in the project's image registry.
- [ ] A Docker image for the backend is built and available in the project's image registry.
- [ ] The frontend and backend are deployed to the designated server environment.
- [ ] The frontend domain points to the server hosting the frontend.
- [ ] The backend domain points to the server hosting the backend.
- [ ] HTTPS works for both domains with valid SSL/TLS certificates.
- [ ] The frontend opens in a web browser through its configured domain.
- [ ] The backend accepts HTTP requests through its configured domain.
- [ ] The frontend loads correctly when a user opens a client-side route directly.
- [ ] The deployed frontend can communicate with the deployed backend through the backend domain.

## Sub-issues

- Create and publish the frontend Docker image.
- Create and publish the backend Docker image.
- Deploy the backend and expose its HTTP API through the server.
- Configure the frontend and backend domains to point to the server.
- Configure HTTPS certificates for both domains.
- Deploy the frontend and configure client-side route handling.
- Configure communication between the frontend and backend domains.
- Verify the frontend, backend, HTTPS, routing and communication through the domains.
