## Technical Story - Testability

Som udviklingsteam vil vi vurdere testability i en eksisterende 
del af systemet, så relevante dele af løsningen kan testes 
isoleret og effektivt.

## Acceptkriterier

- [ ] Teamet har udvalgt en relevant del af den eksisterende løsning. 
- [ ] Afhængigheder, der påvirker testability, er identificeret. 
- [ ] Teamet har vurderet fx separation of concerns, direkte afhængigheder og 
mulighed for dependency injection/test doubles. 
- [ ] Eventuelle problemer med testability er dokumenteret. 
- [ ] Hvis relevant er designet refaktoreret for at forbedre testability. 
- [ ] Teamet kan demonstrere, hvordan ændringen gør testning lettere.
## Sub-issues

- [TESTING] Select a relevant part of the existing solution to assess for testability.
- [TESTING] Identify dependencies that affect how the selected part can be tested.
- [TESTING] Assess separation of concerns, direct dependencies and the use of dependency injection or test doubles.
- [TESTING] Document any testability problems found.
- [TESTING] Refactor the design when relevant to improve testability.
- [TESTING] Demonstrate how any changes make testing easier.
